# Purerify

Purerify is a personal iOS app (SwiftUI + SwiftPM, targeting iOS 17+) that saves YouTube audio for offline playback, built and installed on an iPhone with [xtool](https://github.com/xtool-org/xtool) (no Mac required). A small local Python server (FastAPI + yt-dlp + ffmpeg) performs the actual download/conversion to `.m4a`, and the phone fetches the resulting file over the LAN. The app also supports Spotify playlist import (searching YouTube for each track) and a full offline music library with playlists, shuffle/repeat, background audio and lock-screen controls.

> Only save content you own or have permission to download. Follow YouTube's Terms of Service. YouTube's undocumented playback responses can change at any time and break resolution/downloads.

## Features

### App (iOS)
- Paste a YouTube URL (watch, youtu.be, shorts, embed, live) and resolve title/author.
- Download the audio to the app's private on-device library as `.m4a` (AAC).
- Offline playback with seek slider, play/pause, previous/next, shuffle, repeat (off/all/one).
- Background audio + lock-screen / Control Center controls (MPRemoteCommandCenter, MPNowPlayingInfoCenter).
- Audio session interruption handling (calls, Siri, etc.).
- Library view with song list and playlists (create, rename, delete, add/remove tracks).
- Spotify playlist import: paste a public Spotify playlist URL; the server fetches its tracks, the app searches YouTube for each, converts and saves them, and builds a matching playlist.
- Configurable server base URL (stored in UserDefaults), with a dev-only URLSession that trusts the server's self-signed HTTPS cert.
- Mini player + full "Now Playing" sheet.

### Server (`server/`)
- FastAPI app exposing:
  - `GET /health`
  - `POST /convert` — validates YouTube URL, uses yt-dlp to fetch best audio, ffmpeg-extracts to `.m4a`, stores in `server/storage/`, returns metadata + downloadable `audioUrl`.
  - `POST /spotify/playlist` — fetches a public Spotify playlist (Spotify Web API, client-credentials) with pagination.
  - `POST /search/youtube` — yt-dlp `ytsearch1:` lookup returning the first match.
- Serves stored files via `/files/*` (StaticFiles).
- Cleans up files older than 24 hours on each convert.
- HTTPS via self-signed cert (generated by `generate_cert.py`), port 8443.
- Optional public tunnel via cloudflared (see `server/serverSTART.txt`).

## Architecture

```

├── Package.swift                 # SwiftPM, iOS 17, single target
├── xtool.yml                     # bundle id, info plist, icon
├── Purerify-Info.plist           # UIBackgroundModes: audio
├── Sources/Purerify/
│   ├── PurerifyApp.swift         # @main App
│   ├── ContentView.swift         # UI + PurerifyModel (state, playback, library, playlists, Spotify import)
│   ├── ServerConverter.swift     # HTTP client to local server + models + ServerNetwork (trusts self-signed)
│   ├── YouTubeResolver.swift     # Legacy direct InnerTube resolver + AudioDownloader (chunked Range downloads)
│   └── WebStreamCapture.swift    # Fallback: hidden WKWebView captures PO-token audio URL
├── server/
│   ├── main.py                   # FastAPI server
│   ├── requirements.txt
│   ├── generate_cert.py          # self-signed cert with LAN IP SANs
│   ├── run.bat / run.sh         # uvicorn with SSL
│   └── serverSTART.txt          # server + cloudflared instructions
├── Resources/AppIcon.png
├── youtube-url-converter.html    # standalone client-side URL normalizer (utility)
└── typescript                    # (empty placeholder)
```

### Data flow (current)
1. User pastes YouTube link on Home tab → app calls `POST /convert` on the local server.
2. Server runs yt-dlp + ffmpeg, stores `.m4a`, returns `audioUrl` + metadata.
3. App downloads `audioUrl` into `Application Support/PurerifyLibrary/*.m4a`.
4. Library tab lists saved files; playback uses `AVPlayer` with background audio session.

`YouTubeResolver.swift` and `WebStreamCapture.swift` contain an older direct-from-phone InnerTube path (kept as fallback/reference) that is no longer used by the UI, which now delegates entirely to the server.

### On-device storage
- Audio: `FileManager` application support dir → `PurerifyLibrary/` (file protection `completeUntilFirstUserAuthentication`).
- Playlists: `playlists.json` in the same directory.
- Server base URL: `UserDefaults` key `PurerifyServerBaseURL` (default `https://192.168.1.6:8443`).

## Build & Run (Windows via WSL)

xtool needs Linux/WSL on Windows. Install WSL2 + Ubuntu, then Swift, xtool, USB device access and the iOS SDK per xtool's Linux/Windows guide. The iOS SDK comes from Xcode and needs an Apple ID.

```sh
cd /mnt/d/ai\ proj/ios.apps/Purerify
xtool dev
```

First install needs Apple ID signing + Developer Mode on the iPhone. Free Apple ID provisioning is temporary — rebuild periodically. App updates keep the local library; deleting the app may remove it.

## Server Setup

```sh
cd server
python generate_cert.py          # creates key.pem / cert.pem (with your LAN IP as SAN)
# Windows:
run.bat
# or Linux/macOS:
./run.sh
```

Then set the app's "SERVER URL" to your machine's LAN address, e.g. `https://192.168.1.x:8443`.

### Spotify import
Set env vars before starting the server:
```sh
export SPOTIFY_CLIENT_ID=...
export SPOTIFY_CLIENT_SECRET=...
```
In the app: Library → Spotify import button → paste a public playlist URL → Import. Requires a Spotify app (client credentials). Tracks are matched via YouTube search and downloaded as `.m4a`.

### Public tunnel
```sh
cloudflared tunnel --url https://localhost:8443 --no-tls-verify --no-autoupdate
```
Use the printed `https://...trycloudflare.com` URL as the server URL (useful outside the LAN).

## Requirements

- Xcode/iOS SDK 17+ (via xtool), Swift 6.0 toolchain.
- iPhone 15 Pro or newer recommended; minimum deployment target iOS 17.
- Server: Python 3.10+, ffmpeg (yt-dlp uses it), node (yt-dlp JS runtime), packages in `server/requirements.txt` (fastapi, uvicorn, yt-dlp; generate_cert needs `cryptography`).

## Notes / Caveats

- `ServerNetwork` trusts all server certificates (dev-only) so the self-signed local HTTPS server works.
- `YouTubeResolver`/`AudioDownloader` remain in the codebase as the legacy direct-resolution path; the UI now uses the server.
- Web stream capture (`WebStreamCapture`) is a fallback for PO-token-gated streams; not wired into the current flow.
- Storage files are cleaned after 24 hours; the app's on-device library is unaffected.
